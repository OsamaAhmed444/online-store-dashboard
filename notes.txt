Date: 2026-09-06 (session 2) — Orders, Carts, Settings

What was fixed/built:
- OrdersTable, Modal, and (indirectly used) ProductForm were stub placeholders rendering nothing (`<div>OrdersTable</div>` etc.). Implemented OrdersTable and Modal for real; ProductForm is unused dead code (AddProductPage has its own inline form) so it was left alone.
- OrderStatusBadge used dynamic Tailwind class names (`bg-${color}-100`) that Tailwind can never generate at build time, so status badges had no color at all. Rewrote it to use the existing `.status-badge` CSS system.
- Fixed a CSS bug where pending/processing/confirmed/shipped/delivered orders all rendered with the exact same green badge (only "cancelled" had its own color). Each status now has a distinct color, including "returned" which had no style at all.
- Rebuilt /dashboard/orders (OrdersListPage): it was calling `axios.get` directly (bypassing the app's configured `api` instance/interceptor) with an Authorization header built from `user?.token`, a field that never exists on the user object (token is stored separately in AuthContext) — so every request went out unauthenticated. Now uses `getOrdersAdmin()` / `getProducts()`. Added search, status filter, date-range filter, stats cards, and pagination, and switched the page from a mismatched light Tailwind theme to the app's real dark/orange design system (same pattern as Products/Users pages).
- Orders are now filtered to only the current team's orders: an order is included only if at least one line item's product has subcategory or tags equal to "team-1-product" (same convention already used in components/charts/RevenueLineChart.jsx).
- Rebuilt /dashboard/carts (CartsViewPage): it rendered hardcoded mock data and was never added to App.jsx's routes, so the Sidebar's "Carts" link went nowhere (fell through to the catch-all redirect). Added the route, wired it to the real `getCarts()` API, matched the dark theme, and added a "View" modal listing cart items.
- Added /dashboard/settings: the Sidebar already linked to it but the page and route never existed. Built a Profile Information card and a Security (change password) card wired to the real users API (`updateUser`).
- Fixed the shared Modal component (`common/Modal.jsx`) — it was a `<div>Modal</div>` stub that ignored isOpen/onClose/children entirely, so anything using it (e.g. the unused OrderDetailModal) was broken. It's now a real dialog and is used by the new Carts "view" modal.
- Fixed the shared Button component: it emitted classes like `btn btn-primary btn-md`, but no CSS for `.btn`/`.btn-primary`/etc. existed anywhere except deep inside the product-create page's form, so Button rendered unstyled everywhere else. Added base button styles.
- Changed the Category field on the Add/Edit Product form from free text to a `<select>` populated from existing product categories, with an "Add new category" option that reveals a text field when a genuinely new category is needed.
- Added `setUser` to AuthContext so saving profile changes on the Settings page updates the logged-in session (Topbar, etc.) immediately instead of only the local form.

Date: 2026-09-06 (session 3) — Product Details page + Edit Product modal

Context: no design PDF/image file actually reached this session (only a detailed text brief describing the two screens), so the existing dark/orange design system already in index.css was kept rather than introducing a clashing cyan/blue palette. All changes reuse the existing API layer (api/products.js), AuthContext, and shared components (Modal, Button, Spinner, ImageUploader) — no new API endpoints, no fake data, no parallel auth.

What was found:
- ViewProductPage.jsx (route /dashboard/products/:id/view) already existed as a working, fully API-driven Product Details page with a real getProductById call, loading/error states, and an image gallery — it just lacked prev/next arrows, carousel indicators, and a clearer sectioned layout for price/discount/stock/SKU/brand/tags.
- The "Edit Product modal" already existed too: App.jsx's QuickEditModalHost listens for a `quick-edit-product` window event (dispatched from the Products list "Quick Edit" button) and renders the existing AddProductPage form (which already supports both create and edit via a productId/onClose prop) inside the shared Modal component with a wide `.full-product-edit-modal` layout. It already fetched the real product, populated every field/tag/image from the API, supported adding/removing images, and called the real updateProduct (PATCH /products/update/:id) on save, refreshing the list via a `products-refresh` event.
- ProductsListPage.jsx had a second, half-built quick-edit mechanism (quickEditTarget/quickEditForm/saveQuickEdit calling updateProduct directly) whose modal UI was never actually rendered anywhere — pure dead state left over from an earlier session.

What was changed:
- ViewProductPage.jsx: added left/right navigation arrows and dot indicators to the main product image (only when there is more than one image), and restructured the right column into distinct rounded info cards — Overview/Description, Price + Discount + Stock, Product Information (SKU/Brand/Category/Subcategory/Active), and Tags — instead of one flat block. All values still come straight from the real API response with the same graceful fallbacks as before (name||title, description||shortDescription, stock||quantity, etc.).
- index.css: added `.product-detail-nav-arrow`, `.product-detail-indicators`, and `.product-detail-info-card`/`.product-detail-pricing` rules (dark theme + light-theme overrides) for the above, reusing the app's existing color tokens.
- AddProductPage.jsx (the component behind both the full Add/Edit pages and the Edit Product modal): replaced the plain Featured/Active checkboxes with proper toggle buttons (Featured/Active), which better match "status control" styling and are driven by the same form state that's already populated from and submitted to the real API. Updated the gallery section copy to say "Product Gallery" and clarify that existing images are shown and can be removed/added to, when in edit mode.
- index.css: added `.status-toggle-button` styles for the new toggle buttons and made `.product-toggles` wrap on narrow screens.
- ProductsListPage.jsx: removed the dead, never-rendered quickEditTarget/quickEditForm/quickEditSaving state and its unused updateProduct/Modal imports, since the working Edit Product modal is the one in App.jsx/QuickEditModalHost — this avoids two competing, out-of-sync "quick edit" implementations touching the same API.

- No API endpoints, field names, or auth handling were changed — only presentation/markup around the existing getProductById/updateProduct calls.
